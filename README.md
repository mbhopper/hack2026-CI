# Последний круг

Пиксельный 2D-детектив по кейсу банка «Центр-инвест»: гонщик погибает на трассе, игрок-детектив ищет убийцу.

Сейчас в репозитории: главная страница, вход и регистрация, вступительная катсцена, три локации с ходьбой детектива по клику и выбор подозреваемого. Допросы — следующий этап.

## Как устроена игра

1. **Катсцена** (`/intro`, ~95 секунд, 12 сцен). Рисуется на одном canvas 320×180 и масштабируется целым множителем, поэтому пиксели остаются чёткими. Стиль тот же, что у листов персонажей: чиби, тёмный контур `#0b0f0e`, свет сверху слева, квантованный свет и виньетка. Механики, детектив и «пятый механик» — PNG-листы (`src/assets/characters/`, `src/assets/cutscene/`), болиды и обломки — пиксельные карты в коде (`src/game/cars.ts`), фоны процедурные с кешем (`src/game/scenery.ts`, `src/game/lighting.ts`). Все звуки и музыка синтезируются Web Audio (`src/game/audio.ts`), аудиофайлов нет. Esc — пропустить, пробел — пауза.
2. **Локации** (`/locations`). После катсцены — меню из трёх локаций: место аварии, бокс №7 и VIP-ложа (`/locations/:id`). Детектив идёт туда, куда кликнули (поиск пути — `src/game/pathfinding.ts`). Когда он подходит к улике, над ним появляется «!» и кнопка «Осмотреть» (или клавиша E). Дождь идёт только на месте аварии. Кнопка «К подозреваемым» в меню открывается, когда осмотрены все улики. Данные локаций — `src/game/locations/`, тексты улик — `src/game/story.ts`.
3. **Выбор подозреваемого** (`/suspects`). Стрелки ◀ ▶ (или ← → на клавиатуре) листают пилота №22, механика и спонсора, под портретом кнопка «Выбрать подозреваемого». Ведёт на заглушку допроса `/suspects/:id`.

Сценарий катсцены — массив сцен в `src/cutscene/script.ts`: у каждой есть длительность, функция отрисовки, звуковые события и текст поверх кадра. Тексты улик и подозреваемых — в `src/game/story.ts`. Прогресс (просмотрена ли катсцена, какие улики найдены) пока хранится в `localStorage` (`src/game/progress.ts`).

## Запуск

```bash
npm install
npm run dev      # дев-сервер
npm run build    # сборка в dist/
npm run preview  # просмотр собранной версии
npm run lint     # oxlint
```

## Стек

Vite + React 19 + TypeScript, react-router-dom, обычный CSS с токенами в `src/styles/tokens.css`. Пиксельный шрифт — Press Start 2P, текст — Montserrat (оба локально через `@fontsource`).

## Структура

```
src/
  api/        слой запросов: контракт с бэкендом, http-клиент, мок
  auth/       контекст авторизации (AuthProvider, useAuth, RequireAuth)
  components/ переиспользуемые блоки: PageShell, TrackBackdrop, Button, Field, AuthCard
  pages/      HomePage, LoginPage, RegisterPage, IntroPage, LocationsPage, LocationPage, SuspectsPage, InterrogationPage
  cutscene/   движок катсцены и сценарий 12 сцен
  assets/     картинки: characters/ (листы ходьбы 96×128, ячейка 32×32), portraits/ (портреты 62×62 с эмоциями),
              locations/ (фоны локаций 320×180), cutscene/ (пятый механик и инженер)
  game/       болиды, фоны и свет катсцены, синтез звука, улики и подозреваемые, прогресс, поиск пути,
              characters.ts (отрисовка листов ходьбы), portraits.ts, locations/ (данные локаций)
  lib/        валидация форм
  styles/     токены и глобальные стили
  routes.ts   пути приложения
```

Маршруты: `/` — главная, `/login` — вход, `/register` — регистрация; только для авторизованных: `/intro` — катсцена, `/locations` — меню локаций, `/locations/:id` — локация, `/suspects` — выбор подозреваемого, `/suspects/:id` — допрос.

## Подключение настоящего бэкенда

Пока `VITE_API_URL` не задан, работает мок в `localStorage` (`src/api/auth.mock.ts`): он повторяет ответы и ошибки будущего API. Как только появится сервер, достаточно положить адрес в `.env`:

```
VITE_API_URL=https://api.example.ru
```

и приложение само переключится на `src/api/auth.http.ts`. Сервер должен отдавать:

| Метод  | Путь             | Тело                      | Ответ                        |
| ------ | ---------------- | ------------------------- | ---------------------------- |
| `POST` | `/auth/register` | `{ nickname, password }`  | `{ token, user }`            |
| `POST` | `/auth/login`    | `{ nickname, password }`  | `{ token, user }`            |
| `GET`  | `/auth/me`       | —                         | `user`                       |
| `POST` | `/auth/logout`   | —                         | `204`                        |

Токен передаётся заголовком `Authorization: Bearer <token>`, формы ответов описаны в `src/api/types.ts`. Ошибки — обычные HTTP-коды с телом `{ "message": "текст для пользователя" }`.

По условию кейса регистрация идёт без почты и телефона — только никнейм и пароль.
